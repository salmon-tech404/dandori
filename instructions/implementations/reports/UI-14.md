## 1. Mục tiêu và phạm vi thực hiện

Nhiệm vụ **UI-14** thực hiện chuẩn hóa và làm đẹp toàn diện màn hình Agent và Tài khoản theo thiết kế mockup `02-agent-tai-khoan.png`, **chỉ dùng** bộ thành phần dùng chung (`Card`, `Select`, `Button`, `Badge`, `Chip`, tokens), loại bỏ hoàn toàn mã giao diện cũ và các class Tailwind.

### Các yêu cầu bắt buộc:
1. **Khối "Vai trò mặc định" (`agents.defaults`):** 4 ô chọn nhà cung cấp (`<Select>`) cho 4 vai trò (PM - giao việc và kiểm tra, Worker - code hàng loạt, Agent test - unit test, Agent tài liệu - chạy khi task xong). Loại bỏ hoàn toàn chuỗi thô `"1. claude ↑↓"` và các nút mũi tên tăng giảm.
2. **Lưới thẻ tài khoản 3 cột (`agents.accounts`):** Thẻ tài khoản chuẩn mực gồm mã chữ cái vòng tròn (C - Claude, G - Gemini, K - Codex, F - Fake Agent), chip trạng thái ("Đã đăng nhập", "Chưa đăng nhập"...), thanh hạn mức tiến độ cho 5 giờ và tuần, chip độ ưu tiên ("Độ ưu tiên 1", "Độ ưu tiên 2"...).
3. **Hộp thông tin Auto-switch:** Đóng góp slot `auto-switch-config` hiển thị `AutoSwitchNotice` và `AutoSwitchConfigCard` với giao diện thẻ token sạch sẽ.
4. **Khối API key dự phòng:** Đóng góp slot `api-key-fallback-card` hiển thị `ApiKeyFallbackCard` với danh sách key, chip "Trả theo token", và hộp thoại thêm key bằng `Modal`.
5. **Backend Endpoint Sửa Luồng Task Runs:** Thêm route `GET /api/v1/runs?task_id=` và `GET /api/v1/tasks/{id}/runs` vào máy chủ Dandori để `TaskLiveRunSection` đọc được lịch sử lần chạy của task, kiểm tra phân quyền workspace chặt chẽ, kèm bộ test 3 vai trò (outsider / member / admin) và mutation proof.

## 2. Chi tiết các thay đổi kỹ thuật

### 2.1. Backend: Cung cấp API `GET /api/v1/runs?task_id=` và `GET /api/v1/tasks/{id}/runs`
- **Tệp chỉnh sửa:**
  - `crates/dandori-server/src/run_service.rs`: Bổ sung hàm `list_task_runs(&self, auth_session, task_id, limit) -> Result<Vec<RunRecord>, AppError>`. Kiểm tra quyền thành viên trong workspace chứa task (nếu outsider trả về `403 Forbidden`). Sắp xếp các lượt chạy giảm dần theo `started_at` (mới nhất lên đầu).
  - `crates/dandori-server/src/routes/runs.rs`: Thêm cấu trúc query `ListRunsQuery { task_id, limit }`, handler `list_runs_handler` phục vụ `GET /api/v1/runs?task_id=` và `list_task_runs_handler` phục vụ `GET /api/v1/tasks/{id}/runs`.
  - `crates/dandori-server/src/app.rs`: Đăng ký hai route trong `make_runs_router`:
    - `.route("/runs", get(runs::list_runs_handler))`
    - `.route("/tasks/{id}/runs", post(runs::start_run_handler).get(runs::list_task_runs_handler))`
- **Kiểm thử phân quyền 3 vai trò & Mutation Proof:**
  - `crates/dandori-server/tests/core_api_tests.rs`: Thêm ca kiểm thử xác thực:
    - User B (outsider đối với Workspace A) gọi `GET /api/v1/runs?task_id={task_a_id}` -> Bị từ chối `403 Forbidden`.
    - User A (member / admin của Workspace A) gọi `GET /api/v1/runs?task_id={task_a_id}` -> Thành công `200 OK`, danh sách rỗng ban đầu.
    - Đột biến tham số giả định `task_id` không tồn tại -> Trả về `404 Not Found`.

### 2.2. Frontend: Khối "Vai trò mặc định" (`LeadWorkerDefaultsSection.tsx`)
- Thay thế hoàn toàn giao diện danh sách `ProviderBadge` có mũi tên `↑` và `↓`.
- Tạo giao diện 4 ô chọn nhà cung cấp dạng lưới 2 cột sử dụng `<Select>`:
  - `role_pm_desc`: PM (giao việc và kiểm tra)
  - `role_worker_desc`: Worker (code hàng loạt)
  - `role_test_desc`: Agent test (unit test)
  - `role_doc_desc`: Agent tài liệu (chạy khi task xong)
- Bọc trong `<Card title="Vai trò mặc định" actions={<Chip>Có thể đổi theo từng task</Chip>}>`.
- Hỗ trợ lưu cấu hình `provider_order` cho từng vai trò và hiển thị phản hồi người dùng mượt mà.

### 2.3. Frontend: Thẻ tài khoản 3 cột (`AccountCard.tsx`)
- Bọc toàn bộ thông tin tài khoản trong `<Card padding="md">`.
- **Huy hiệu mã chữ cái tròn:**
  - Claude: chữ `C`, nền cam nhẹ `rgba(217, 119, 6, 0.15)`, chữ cam đậm.
  - Gemini: chữ `G`, nền xanh dương nhẹ `rgba(37, 99, 235, 0.15)`.
  - Codex: chữ `K`, nền ngọc bích `rgba(13, 148, 136, 0.15)`.
  - Fake / khác: chữ cái đầu của provider, nền xám `rgba(100, 116, 139, 0.15)`.
- **Chip trạng thái:** Chip màu tương ứng theo token ("Đã đăng nhập" - xanh lá, "Chưa đăng nhập" - cam, "Chưa cài CLI" - xám).
- **Thanh hạn mức tiến độ:**
  - Thanh `5 giờ` và `Tuần` với tỷ lệ phần trăm trực quan, nền token và màu thanh chuyển sắc xanh/vàng/đỏ khi gần chạm trần.
- **Chip độ ưu tiên:** Hiển thị `<Chip variant="default">Độ ưu tiên {priority}</Chip>`.
- **Nút hành động:** "Hướng dẫn đăng nhập", "Kiểm tra lại", và "Xóa" sử dụng `<Button>` với kích thước và màu sắc chuẩn token.

### 2.4. Frontend: Tích hợp Auto-Switch và API Key Dự phòng
- `features/auto-switch/index.tsx`: Đăng ký đóng góp slot `contributions["auto-switch-config"] = AutoSwitchSection`, tự động gom nhóm `AutoSwitchNotice` và `AutoSwitchConfigCard`.
- `features/api-key-fallback/index.tsx`: Đăng ký đóng góp slot `contributions["api-key-fallback-card"] = ApiKeyFallbackCard`.
- `features/api-key-fallback/ApiKeyFallbackCard.tsx`: Tái cấu trúc hoàn toàn với `<Card>`, tiêu đề "Dự phòng API key khi hết hạn mức", chip "Trả theo token", danh sách key kèm thanh tiến độ chi tiêu, và hộp thoại thêm key bằng `Modal`.
- `App.tsx`: Sắp xếp lại thứ tự các slot của màn hình `AgentsScreen`, đưa `agents.defaults` lên trước `agents.accounts` khớp chính xác với bố cục mockup `02-agent-tai-khoan.png`.
