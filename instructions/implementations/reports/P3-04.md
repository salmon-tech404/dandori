## 1. Mục tiêu và Phạm vi Task P3-04

Task P3-04 triển khai module **`overnight-queue`** (Hàng đợi chạy qua đêm) cho phép người dùng gom các tác vụ nặng cần nhiều thời gian để hệ thống tự động xử lý tuần tự qua đêm theo thứ tự ưu tiên:
- Hỗ trợ xếp hàng nhiệm vụ theo thứ tự ưu tiên `order_index`.
- Giới hạn số lượng tác vụ chạy song song $N$ (mặc định $N = 1$ để tránh làm nghẽn tài nguyên và chạm quota API).
- Giờ bắt đầu cấu hình được (`start_time`, mặc định `23:00`).
- Cơ chế **Dừng an toàn (Safe Stop)**: Khi gặp chuỗi thất bại liên tiếp $K$ lần (mặc định $K = 3$, cấu hình được qua `consecutive_failure_limit`), hàng đợi tự động chuyển sang trạng thái `stopped` để bảo toàn hạn mức tài khoản và không tiêu tốn quota vô ích.
- Khôi phục sau khởi động lại: Vị trí hàng đợi được lưu bền vững trong SQLite; khi hệ thống khởi động lại, worker tiếp tục xử lý các task chưa hoàn thành mà không nhân bản hay chạy lại các task đã hoàn thành (`completed`).
- Tự động tổng hợp dữ liệu **"Chuỗi để duyệt" (Morning Review Chain)** sáng hôm sau: thống kê số task hoàn thành, thất bại, cần can thiệp (`needs_human`) kèm danh sách nhánh git làm việc để người dùng duyệt khi thức dậy.
- Tích hợp tôn trọng khung giờ cấm chạy (`quiet-hours`) và bộ lập lịch (`calendar`).
- **An toàn hệ thống tuyệt đối (AC 7)**: Mã nguồn tuyệt đối không chứa bất kỳ lệnh tắt máy (`shutdown`), khởi động lại (`restart`), hay chuyển chế độ ngủ (`sleep`, `hibernate`, `SetSuspendState`).
- Phân quyền và BOLA (AC 6): Phân định rõ 3 vai trò (Outsider bị từ chối 403, Member được xem/xếp hàng/đảo thứ tự, Admin/Owner được cấu hình và điều hành tạm dừng/tiếp tục/khởi động hàng đợi).

## 2. Chi tiết Triển khai Kiến trúc & Mã nguồn

### 2.1 Backend Crate `crates/mod-overnight-queue`
1. **Khai báo module (`crates/mod-overnight-queue/module.json`):**
   - Định danh `overnight-queue`, phiên bản `0.1.0`, thuộc nhóm `scheduling`.
   - Phụ thuộc: `calendar`, `quiet-hours`.
   - Đóng góp UI vào slot `calendar.panel` (`OvernightQueuePanel`).
2. **Lược đồ cơ sở dữ liệu (`migrations/0001_overnight_queue.sql`):**
   - Bảng `m_overnight_queue_config`: lưu trữ cấu hình hàng đợi của workspace (`workspace_id`, `start_time`, `timezone`, `max_concurrency`, `consecutive_failure_limit`, `status`, `consecutive_failures`, `last_run_summary`, `updated_at`).
   - Bảng `m_overnight_queue_item`: lưu trữ các mục trong hàng đợi (`id`, `workspace_id`, `task_id`, `order_index`, `status`, `run_id`, `created_at`, `updated_at`).
   - Chỉ mục `idx_m_overnight_queue_ws_order` và `idx_m_overnight_queue_task` tối ưu hóa truy vấn thứ tự thực thi.
3. **Worker nền (`src/worker.rs`):**
   - Cung cấp trừu tượng `Clock` (`RealClock` / `MockClock`) phục vụ kiểm thử đơn vị độc lập với đồng hồ hệ thống.
   - Vòng lặp `run_overnight_queue_worker` điều phối hàng đợi theo `start_time` và `CancellationToken`.
   - Hàm `process_overnight_queues`: kiểm tra trạng thái hàng đợi, đếm số lượng tác vụ đang chạy so với `max_concurrency`.
   - Xử lý dừng an toàn khi đếm `consecutive_failures >= consecutive_failure_limit`: đánh dấu `status = 'stopped'`, tổng hợp tóm tắt sáng và phát sự kiện `overnight_queue.stopped` qua `EventBus`.
   - Khi hoàn tất toàn bộ task hoặc dừng an toàn, gọi `finalize_overnight_queue` để tổng hợp số liệu "Chuỗi để duyệt" và lưu vào `last_run_summary`.
4. **REST API Router (`src/routes.rs`):**
   - `GET /workspaces/{ws_id}/queue`: Lấy cấu hình và danh sách task kèm trạng thái chi tiết (yêu cầu `can_access_workspace`).
   - `PUT /workspaces/{ws_id}/queue`: Cập nhật cấu hình hàng đợi (yêu cầu `can_administer_workspace`).
   - `POST /workspaces/{ws_id}/queue/items`: Thêm danh sách task vào hàng đợi (yêu cầu `can_access_workspace`).
   - `DELETE /workspaces/{ws_id}/queue/items/{item_id}`: Xóa một mục khỏi hàng đợi (yêu cầu `can_access_workspace`).
   - `PUT /workspaces/{ws_id}/queue/reorder`: Sắp xếp lại thứ tự hàng đợi (yêu cầu `can_access_workspace`).
   - `POST /workspaces/{ws_id}/queue/pause`: Tạm dừng hàng đợi (yêu cầu `can_administer_workspace`).
   - `POST /workspaces/{ws_id}/queue/resume`: Tiếp tục hàng đợi (yêu cầu `can_administer_workspace`).
   - `POST /workspaces/{ws_id}/queue/start-now`: Khởi động hàng đợi ngay lập tức (yêu cầu `can_administer_workspace`).
   - `GET /workspaces/{ws_id}/queue/summary`: Lấy tóm tắt chuỗi để duyệt sáng hôm sau (yêu cầu `can_access_workspace`).

### 2.2 Giao diện Người dùng TypeScript / React (`frontend/app/src/features/overnight-queue/`)
- `types.ts`: Định nghĩa kiểu dữ liệu `OvernightQueueConfig`, `OvernightQueueItem`, `QueueItemWithTask`, `MorningSummaryDto`, `ReviewChainItem`.
- `api.ts`: API client giao tiếp với backend module.
- `useOvernightQueue.ts`: React hook quản lý trạng thái tải dữ liệu, cập nhật và thao tác điều hành hàng đợi.
- `MorningReviewChainBanner.tsx`: Hiển thị banner tóm tắt sáng hôm sau ("Chuỗi để duyệt") với thống kê hoàn thành / thất bại / cần can thiệp và nhánh git.
- `OvernightQueuePanel.tsx`: Bảng điều khiển quản lý hàng đợi, hiển thị giờ bắt đầu, trạng thái, danh sách nhiệm vụ kèm nút Lên / Xuống / Xóa và nút Tạm dừng / Tiếp tục / Chạy ngay.
- `i18n.ts`: Bổ sung toàn bộ từ khóa bản địa hóa tiếng Việt `overnight_queue_*`.
